# VulnAgent 项目总体说明

## 1. 项目名称

中文名称：

**基于大模型多智能体的软件漏洞挖掘与验证系统**

英文名称：

**VulnAgent: An LLM-based Multi-Agent Software Vulnerability Discovery and Verification System**

## 2. 项目背景

软件漏洞挖掘是网络空间安全中的重要研究与工程问题。

传统的软件漏洞分析方法主要包括：

- 静态程序分析
- 动态程序分析
- 模糊测试
- 符号执行
- 人工逆向分析
- 基于规则的漏洞扫描

不同技术各有优势，但也存在明显局限。

静态分析具有较好的代码覆盖能力，但容易产生误报；动态测试能够获得真实运行结果，但受输入空间和覆盖率限制；模糊测试擅长发现异常行为，但通常缺乏程序语义理解；大语言模型具有较强的代码理解与语义推理能力，但单独使用时又存在幻觉、结果不稳定以及证据不足等问题。

因此，本项目尝试将大语言模型、多智能体协同、静态程序分析、二进制分析和动态测试进行融合，构建一套具有完整漏洞证据链和独立复核能力的软件漏洞挖掘系统。

## 3. 项目目标

VulnAgent 的总体目标是设计并实现一个能够面向源代码和二进制程序执行自动化漏洞分析的软件安全平台。

系统希望实现以下基本流程：

1. 接收待分析目标；
2. 判断目标类型和分析能力；
3. 对目标执行程序结构分析；
4. 根据程序结构生成漏洞分析计划；
5. 执行静态或二进制分析；
6. 生成候选漏洞；
7. 根据候选漏洞指导动态测试或 Fuzz；
8. 收集程序运行证据；
9. 通过独立 Agent 对候选漏洞进行复核；
10. 构建漏洞证据链；
11. 对结果进行去重和严重度分析；
12. 生成结构化漏洞分析报告。

## 4. 项目核心思想

VulnAgent 不将大语言模型视为“漏洞扫描器”，而将其作为系统中的推理组件。

系统采取：

**分析工具 + 程序结构信息 + Agent 协作 + LLM 推理 + 运行证据**

的综合思路。

总体流程：

```text
Target
  │
  ▼
Target Profiler
  │
  ▼
Planner Agent
  │
  ├───────────────┐
  ▼               ▼
Source Analysis   Binary Analysis
  │               │
  └───────┬───────┘
          ▼
 Vulnerability Candidates
          │
          ▼
     Fuzz / Runtime
          │
          ▼
      Evidence
          │
          ▼
 Verification Agent
          │
          ▼

          │
          ▼

          │
          ▼

```

## 5. 设计原则

### 5.1 模块化

分析器、Agent、LLM、Fuzz、验证和报告模块应保持低耦合。

### 5.2 可替换

不同 LLM、静态分析工具和动态分析后端可以替换。

### 5.3 可验证

所有创新设计都应能够通过实验验证。

### 5.4 Evidence First

漏洞结论必须尽可能依赖可复核证据，而不是仅依赖模型自然语言判断。

### 5.5 安全执行

二进制运行、Fuzz 和漏洞验证必须位于受控实验环境。

## 6. 初步支持目标

### 源代码

优先：

- C
- C++
- Python

后续根据课程时间扩展。

### 二进制

优先：

- Windows PE
- Linux ELF

## 7. 大语言模型

系统设计统一 LLM Adapter。

目标支持：

- DeepSeek
- GLM
- Kimi

实际课程实验阶段根据环境选择至少两个模型进行横向比较。

## 8. 主要输出

系统输出包括：

- 分析任务
- 程序结构摘要
- 攻击面
- 候选漏洞
- 漏洞证据
- Verification 结果
- Fuzz Crash
- 风险等级
- CWE 类型
- 分析过程
- 最终报告
