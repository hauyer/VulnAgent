# 软件代码安全审计答辩话术

> 仅用于安全审计与防御研究，仅限教学实验使用。

## 30 秒版本

“老师之前指出我们的审计维度偏交互层，所以这次不是再多加几个 Prompt，而是新增了软件代码安全域。系统先用 Tree-sitter 解析 Go、C、C++，构建 AST 和函数内 CFG，再从 API 参数、网络输入追踪到拷贝、分配和数组下标等敏感位置。规则命中后仍只是候选，代码审计 Agent 做语义复核，最后由独立 VerificationAgent 结合 Evidence ID 给出确认、排除或存疑结论。”

## 动态验证怎么讲

“动态部分严格定义为本地健壮性验证，只生成空值、边界值、受限超长字符串和类型异常，不做代码执行或提权。引擎只接受回环地址，并要求沙箱证明低权限、无外网、只读和可重置；证明不满足就拒绝运行，测试后无论成功失败都会重置环境。”

## 技术深度怎么讲

“技术深度主要体现在三点：第一，AST、CFG 和污点路径提供了可解释的数据流证据；第二，模型只能研判误报，不能直接确认漏洞，避免把自然语言当证据；第三，源码定位、规则、动态日志、智能体摘要和独立复核都进入同一条证据链，最后自动形成漏洞卷宗和报告。”

## 老师追问当前完成度

“Go/C/C++ 解析、核心内存/边界/输入校验规则、代码审计 Agent、卷宗和报告链路已经实装并有单元测试。动态验证的核心接口、回环限制、沙箱证明、监控分类、脱敏证据和自动重置已经完成；实际隔离执行依赖实验机提供 Sandbox Adapter，未配置时系统会保持关闭，不会在宿主机冒充已经完成动态验证。”

## 一句话安全边界

“我们做的是本地授权软件质量与安全审计，输出证据和修复建议，不输出攻击性实现。”
