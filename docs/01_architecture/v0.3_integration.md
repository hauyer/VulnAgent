# V0.3 Integration Architecture

V0.3 keeps the frozen public contracts and the P1 lifecycle intact. The only
formal business path is:

```text
React/Vite -> /api -> FastAPI -> Orchestrator -> AgentRuntime
                                      -> CapabilityBundle
                                      -> Evidence -> Verification -> Report
```

`src/vulnagent/core/orchestrator.py` is the sole task lifecycle owner.
`TaskRepository`, `EvidenceRepository`, and `ContextRepository` are the single
state source. They are process-local by default; with `STORAGE_BACKEND=sqlite`,
one injected `SQLiteRepository` persists all three aggregates without exposing
SQL to Core or Agents. Vite is only a development server and `/api` proxy; no
TypeScript task manager, verifier, report generator, or orchestrator is retained.

SQLite restores completed or failed API aggregates after restart. It does not
claim checkpoint/resume for an Agent that was in flight when the process ended.

## Profiles

- `mock`: deterministic V0.2 architecture and CI fallback.
- `v03-source`: real `SourceProjectParser`, `PythonSourceAuditor`,
  `EvidenceVerifier`, and `StructuredReportGenerator`; bounded static binary
  inspection is followed by registered `binary.logic` and
  `binary.obfuscation` semantic capabilities, and controlled fuzzing remains
  opt-in behind explicit target authorization.

The binary route separates low-level facts from higher-level semantics:

```text
binary.inspect -> BinaryAnalysisResult
               -> binary.logic + binary.obfuscation (parallel)
               -> auxiliary Evidence -> Verification -> Report
```

Logic localization and obfuscation scores remain explainable clues. They never
write `CONFIRMED` or bypass independent verification.

Neither profile changes the public Task, AgentMessage,
VulnerabilityCandidate, or Evidence contracts.

## Safety boundaries

Source analysis never executes target code. Static binary analysis never
executes a binary. Fuzzing requires both planner opt-in and explicit target
metadata authorization, uses bounded local process execution, and is intended
only for controlled teaching targets. Runtime traces contain structured events
and public summaries, not private model reasoning.
