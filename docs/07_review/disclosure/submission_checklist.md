# 国家漏洞库提交条件检查清单

配套 `cnvd_submission_template.md`。真实提交国家漏洞库（CNVD/CNNVD）
前，以下每项必须确认；任何一项不满足 → 保持 `UNSUBMITTED`，绝不虚构提交。

## 1. 授权与伦理前置

- [ ] 目标是否在授权范围？（自建/书面授权/明确公开并允许研究的软件）
- [ ] 测试过程是否限定在本地/隔离环境，未触碰生产系统？
- [ ] 是否已评估对真实用户与系统的风险（无破坏性验证、无载荷投递）？
- [ ] 是否遵守厂商披露政策（协调披露时间窗）？

## 2. 漏洞有效性标准

- [ ] 已确认存在漏洞（独立验证 ≥1 种证据：动态崩溃/Sanitizer/修复对照/静态调用链）？
- [ ] 已定位根因（入口 → 调用链 → 危险操作）？
- [ ] 已确认非误报、非重复（对照历史知识表 / 已有 CVE）？
- [ ] 影响版本与修复版本已从权威来源核对？

## 3. CNVD / CNNVD 收录流程（课程口径）

| 步骤 | 说明 |
|---|---|
| 1. 材料整理 | 按模板填写，证据脱敏（不附完整崩溃转储/载荷） |
| 2. 提交渠道 | CNVD 官网/合作单位渠道（真实提交由有权主体操作） |
| 3. 审核受理 | 平台确认材料完整性与漏洞有效性 |
| 4. 收录编号 | 审核通过后分配 CNVD-YYYY-XXXX 编号 |
| 5. 披露 | 按平台规则与协调披露时间窗公开 |

> 课程范围：本清单仅用于**流程演示**，不进行真实提交。

## 4. 提交主体资格

- [ ] 提交人是否为漏洞发现者/授权代表？
- [ ] 单位/个人主体信息是否真实可查？
- [ ] 是否理解并接受平台用户协议与免责条款？

## 5. 材料完整性

- [ ] 基本信息齐全（名称/类型/CWE/版本/危害等级）
- [ ] 复现步骤可执行（他人可按步骤复现）
- [ ] 证据材料已脱敏且可追溯（VulnAgent Evidence ID 引用）
- [ ] 修复建议明确
